ChakraView is a reconnaissance framework for security researchers and bug-bounty hunters. One command runs ten modules against a domain — subdomain enumeration, HTTP fingerprinting, takeover detection, DNS and mail-posture auditing, JavaScript secret mining and port scanning — and returns every finding ranked by severity, with the evidence behind it and a remediation line.

Authorised testing only. Six of the ten chakras send traffic to the target — DNS queries, HTTP requests and TCP connections. Run ChakraView against infrastructure you own or have written permission to test. Use --passive-only when you need reconnaissance that touches third-party sources exclusively.

✦ The formation

Ten chakras, run in order

Each chakra feeds the next. The archive hands hostnames to enumeration, enumeration hands live hosts to the prober, the prober hands fingerprints to the dork generator. Run the whole formation, or name the ones you want with --only.

I

Shakuni github

Organisation repositories, public members, commit-author emails, and authenticated code search for committed credentials.

II

Sanjaya infra

Every address the apex answers with, enriched with ASN and organisation, then classified as origin, CDN edge or hyperscaler.

III

Drona dns

Full record sweep, SPF and DMARC auditing, DKIM selector probing, SaaS tenants visible in TXT, and a zone-transfer attempt against every nameserver.

IV

Ashwatthama archive

The Wayback index, sorted into sensitive extensions, admin paths and the query parameters that map to a known vulnerability class.

V

Karna subs

Eleven passive sources — eight need no API key — merged with a resolved bruteforce, behind wildcard-DNS detection so a wildcard domain cannot inflate the results.

VI

Arjuna http

Status, title, server and technology fingerprint per host, plus exposed .git and .env, reflected CORS, directory listings and missing security headers.

VII

Ekalavya takeover

Sixty-plus provider fingerprints. A CNAME alone is never reported — the provider's unclaimed-name response has to confirm it.

VIII

Abhimanyu ports

TCP connect scan with banner grabbing, severity-rated against the services that should never face the internet.

IX

Sahadeva js

First-party JavaScript only: API routes the application actually calls, and twenty-one credential patterns with placeholder filtering.

X

Brahmastra dorks

Dorks built from what the scan found, emitted as live links for Google, GitHub, Shodan, Censys and the certificate logs.

✦ Install

Four dependencies, no build step

Python 3.10 or newer. Nothing is compiled and nothing is bundled.

Install
# clone and install
git clone https://github.com/mayurie-cysec/chakraview
cd chakraview
pip install -r requirements.txt

# GitHub token. Only needed for code search.
# Everything else runs without it.
export GITHUB_TOKEN=ghp_your_readonly_token
Run it
# in the terminal
python3 chakraview.py -d example.com

# in the browser
python3 chakraview.py --serve

✦ Usage

Scope it to what you need

Run any chakra on its own, or skip the ones you do not need. The default limits are set low so a scan stays quick and quiet. Use --deep to raise every one of them.

ChakraView command-line options
FlagEffect
-d, --domainTarget domain. Accepts a bare domain or a full URL.
-f, --formattxt, json, md, html, or all.
--onlyRun only these chakras: --only subs,http,takeover
--skipSkip these chakras: --skip ports,js
--passive-onlyThird-party sources exclusively. Sends nothing to the target.
--deepRaise every cap: 100 ports, more hosts probed, more scripts mined.
-c, --concurrencyConcurrent requests. Default 50.
-w, --wordlistYour own subdomain wordlist instead of the built-in list.
--portstop10, top25, top100, or 22,80,443.
--plainNo colour, no animation — for CI logs and pipes.
--list-chakrasPrint the roster and exit.

✦ Version 2.0

What changed

v1 brute-forced a wordlist and animated a progress bar after the work had already finished. Both of those are gone.

Bruteforce only — about 300 guesses
→
Eleven passive sources merged with the bruteforce, behind wildcard filtering
A radar bar replayed after the scan ended
→
Progress driven by each module's own counters, with results printed as they are found
Exited immediately without a GitHub token
→
Runs unauthenticated and says which capability the missing token costs
No HTTP probing at all
→
Status, title, server, technology fingerprint, CORS, security headers and exposed-file checks
No takeover detection
→
Sixty-plus provider fingerprints, two-signal confirmation to keep false positives out
Plain-text report only
→
Text, JSON, Markdown and a self-contained HTML page with severity filtering
No severity model — everything printed flat
→
Findings carry severity, evidence and remediation, and roll up into a risk score
